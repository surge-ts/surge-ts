# Compiler API

> **Experimental.** This API is not covered by [PUBLIC_API.md](../PUBLIC_API.md)'s
> stability guarantees yet. Measured agreement with TypeScript belongs in
> [CURRENT_STATUS.md](../CURRENT_STATUS.md), never here.

surge-ts exposes a read-only subset of TypeScript's compiler API, for tools
that would otherwise run `tsc --noEmit` through the `typescript` package:
programs, source files and their syntax trees, and a type checker. It is
available from JavaScript as the `surge-ts` npm package and from Rust as
`surge_ts::api`.

```js
import ts from "surge-ts";

const program = ts.createProgram(["src/index.ts"], { strict: true, noEmit: true });
const checker = program.getTypeChecker();
for (const sourceFile of program.getSourceFiles()) {
	if (sourceFile.isDeclarationFile) continue;
	ts.forEachChild(sourceFile, function visit(node) {
		const symbol = checker.getSymbolAtLocation(node);
		if (symbol) {
			console.log(symbol.getName(), checker.typeToString(checker.getTypeOfSymbolAtLocation(symbol, node)));
		}
		ts.forEachChild(node, visit);
	});
}
const host = ts.createCompilerHost(program.getCompilerOptions());
console.log(ts.formatDiagnostics(ts.getPreEmitDiagnostics(program), host));
```

The same walk in Rust is `crates/surge-ts/examples/api_walk.rs`:

```sh
cargo run -p surge-ts --example api_walk -- --project path/to/tsconfig.json
```

Anything the tables below do not list is not provided, and the package's
types leave it out, so using it is a type error. A method the tables mark ✖
exists and throws an `Error` naming itself (`surge-ts: TypeChecker.getResolvedSignature
is not supported yet`): surge-ts never answers with a guess.

The package's types are typescript@6.0.3's own declarations, shipped as
`lib/typescript.d.ts` (typescript@7 ships none for the JavaScript API):
`index.d.ts` re-exports every type of them and only the values surge-ts
provides. Both are generated by `scripts/api/generate-enums.ts`, which also
re-exports what `lib/internal.d.ts` declares: the part of TypeScript's
internal API surge-ts provides ([below](#typescripts-internal-api)).

## Building the native binding

The package loads a Node addon built from `crates/surge-ts-node`:

```sh
node packages/surge-ts/scripts/build-native.cjs            # debug
node packages/surge-ts/scripts/build-native.cjs --release  # optimized
```

The script writes `packages/surge-ts/surge-ts.<platform>-<arch>.node`. The
loader (`lib/native.cjs`) takes, in order: the file named by the
`SURGE_TS_NATIVE` environment variable, that local build, then an installed
`@surge-ts/binding-<platform>-<arch>` package. No binding package is published
yet.

## Architecture

**One pipeline.** A program is built by the same three steps the CLI runs:
`Project` prepares the run (configuration, module resolution, default
libraries, the import graph), the checker checks the program, and the
prepared finish selects diagnostics. The API differs in one respect only: it
keeps the checked program (`RetainedProgram::check` in `surge-ts-checker`'s
`semantic` module is the one-shot check without its end-of-run teardown and
per-file release). The CLI's output is unchanged by the API's existence.

**Syntax.** The tree the API exposes is `surge-ts-tsc-syntax`'s, the port of
tsgo's parser, parsed per file on first access. Node kinds use TypeScript
6.0.3's `SyntaxKind` numbering, and each node's children carry the property
names TypeScript uses (`name`, `typeParameters`, `body`, …); `forEachChild`
visits them in TypeScript's order. `scripts/api/compare-tree-walk.ts`
compares the walk with typescript@6's over a corpus. Symbols come from the
same crate's binder port: a symbol's name, flags, declarations, members and
exports are the binder's.

**Types.** Types are the checker's. The first query that needs a file's types
checks that file again with a recorder on: hooks at the points where the
checker computes an expression's, a declaration's, a parameter's and a call's
type record it by source span, so a query reads what the checker decided
rather than a second implementation of it. A type written in the source (an
annotation, a signature, a type node) is resolved from its text by the
checker's own parser and resolver, in the scope of the file it is written in.
Where the checker recorded nothing, the answer is the error type, which prints
as `any`, as TypeScript's error type does.

**Binding.** `crates/surge-ts-node` (napi-rs) exposes the Rust API as
handle-based methods; `packages/surge-ts` wraps the handles in
TypeScript-shaped objects. A file's node table crosses the boundary once, as
typed arrays (kinds, positions, parents, children); a node's named children
and text are read when first asked for. Nothing is serialized eagerly.

## Handles and lifetime

- A `Program` owns everything its queries answer from: the checked program,
  the syntax trees, and the per-file type indexes built on demand. It is
  released when the last reference to it goes (Rust: drop; JavaScript: garbage
  collection). The binding reports each program's source text to V8 as
  external memory, so the collector weighs a dropped program by at least
  that much.
- Nodes, types, symbols, signatures and source files are opaque handles
  (`NodeId`, `TypeId`, `SymbolId`, `SignatureId`, `SourceFileId` in Rust),
  valid for the lifetime of the program that issued them. Each carries its
  program's identity. A handle given to another program is rejected: the Rust
  API panics ("belongs to another program"), the JavaScript API throws a
  `TypeError`.
- Asking twice gives the same handle, and in JavaScript the same object:
  `checker.getTypeAtLocation(node) === checker.getTypeAtLocation(node)`.
- A retained program holds what the checker computed for every file of the
  program, about what a CLI run holds at its peak, until the program is
  released. Each file queried adds its type index.
- The checker keeps process-wide state. Programs coexist and answer
  independently: each query installs its own program's state under one
  process-wide lock, so checks and queries run one at a time per process.
  The JavaScript API is synchronous. A program created with a custom
  `CompilerHost` calls the host from the thread that created it.

## Positions

Positions are UTF-16 offsets, as TypeScript reports them. A node's `pos` and
`end` include its leading trivia; `getStart()` skips it. Lines break at `\n`,
`\r\n`, `\r`, U+2028 and U+2029, as `computeLineStarts` does.

## Diagnostics

Compiler diagnostics are data: a program with errors is created, and the
errors are in its diagnostics. `getPreEmitDiagnostics` is TypeScript's
selection (configuration, options, syntactic, global and semantic
diagnostics, and declaration diagnostics when `declaration` is on), sorted
and deduplicated; it reports what the `surge` CLI reports for the same
program. Each diagnostic's `messageText` is a string: message chains are
flattened, and `relatedInformation` is not provided. A diagnostic surge
reports that TypeScript has no code for has `code` 0 and a `surgeCode`
(`surge::project-has-no-source-files`).

## Known differences

Each of these is surge's checker, not the API: its types do not carry what
TypeScript prints or answers there. `packages/surge-ts/test/differential.test.mjs`
holds a minimal reproduction of the first as a `test.fails` case, which
starts failing when the difference is fixed. The list was
re-verified against typescript@6.0.3 on 2026-10-17 (working tree after
`e5fc8b09`); the optional-parameter `| undefined`, initializer narrowing,
written type predicates, block-bodied `void` returns, `Promise<T>` folding,
generic mapped/conditional alias names, `Array<T>`, regular expression and
index signature parameter entries previously listed here no longer differ,
nor (verified the same day) does the declaration of a member read through
a generic instantiation, a primitive, an array, an intersection or a union
of named types. On 2026-10-18 (working tree after `ddd14863`) an
intersection operand written through a type alias was verified to print as
the alias, and a union built from a named union to print that name
(`Filter | "none"`).

- A variable declared with a tuple type alias prints as its tuple:
  `[string, number]` for `declare const pair: Pair`.
- A union orders its literal and named members by where the program first
  writes each, standing for the order TypeScript creates their types in
  (`"on" | "off"` for `'off' : 'on'` after the alias `'on' | 'off'`), and
  its other members as written. Where creation order differs — a type first
  created while resolving a declaration further down, an anonymous object
  type, a literal surge cannot tell is TypeScript's fresh expression type
  rather than its regular one — so does the output.
- An inferred type predicate (`(x) => typeof x === "string"`) prints as
  `boolean`.
- An overloaded function's declaration names print the first overload, and
  some library methods print the signature surge models them with
  (`Promise.resolve` returns `Promise<unknown>`).
- A `const` destructured from an object literal keeps the literal's member
  types (`1` where TypeScript widens to `number`).
- A property of an anonymous object type has no declaration when nothing
  written at the access names its type (an inferred return, a type literal
  written as a type argument).

## Differential testing

- `packages/surge-ts/test/differential.test.mjs` (vitest, `pnpm test` in
  `packages/surge-ts`) checks small projects written per area through
  typescript@6 and surge-ts and requires identical observations: node kinds
  and positions from `forEachChild`, each identifier's symbol name, flags
  and type, and the types of calls, property accesses, binary expressions
  and object literals.
- `scripts/api/compare-api.ts` measures the same agreement over the
  repository's fixture projects (`tests/compat-projects`), split into a
  development set and a held-out set (a fixture is held out when the FNV-1a
  hash of its name is 0 mod 5), per metric: tree structure, symbol presence,
  name, flags and declaration, `getTypeOfSymbolAtLocation` and
  `getTypeAtLocation`. Work against the development set; the held-out set
  checks that a change generalizes.

  ```sh
  node packages/surge-ts/scripts/build-native.cjs
  pnpm exec tsx scripts/api/compare-api.ts --set dev
  pnpm exec tsx scripts/api/compare-api.ts --set held-out
  ```

Emit and declaration emit, transformers, `factory` and the printer, watch

and the language service.

`surge_ts::api` has the same model with handles:

  config_file_parsing_diagnostics })`, `Program::parse_source_file`; files

  position conversion), nodes (`node_kind`, `node_pos`, `node_end`,
  `node_start`, `node_parent`, `node_children`, `node_properties`,
  `node_property`, `node_text`, …) and the diagnostic sets.

  snake case. Queries surge cannot answer return `Err(Unsupported)`.

  `read_config_file`, `parse_config_file_text`,
  `parse_json_config_file_content`, `find_config_file`,
  `resolve_module_name`, `format_diagnostic`.
- `SyntaxKind` and the flag and option enums, generated from typescript@6.0.3
  by `scripts/api/generate-enums.ts`.
